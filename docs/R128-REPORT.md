## Architecture
```
Browser (index.html, block saturn-r128-hl)                      Saturn backend (Saturn-perps-data)             Hyperliquid mainnet
 ├─ Ethereum wallet (EIP-6963: MetaMask, Rabby, …)             └─ /v1/perps/hl/config    (switches, limits)     api.hyperliquid.xyz
 │    signs: ApproveAgent, Withdraw, SendAsset (EIP-712)          /v1/perps/hl/markets   (mainnet discovery)  ┌ /info     (reads)
 │    sends: Arbitrum USDC → Bridge2 (deposit only)               /v1/perps/hl/exchange ── checks + audit ──→ └ /exchange (writes)
 ├─ trading key (agent): signs orders/cancels/leverage (L1, mainnet phantom agent "a")
 ├─ reads /info directly (public, no signature)
 └─ Solana wallet + Jupiter path for SOL/ETH/BTC: untouched
```
- **Two venue adapters, one wire protocol.**
  - Hyperliquid crypto perps use asset id = index in the `meta` universe.
  - Trade.xyz uses dex `xyz`; asset id = `100000 + dexIndex×10000 + index` (from `perpDexs`). Its collateral token must be 0 (USDC), or the market is refused. Its fee multiplier is 2× (HIP-3).
  - Coins come from the backend registry (SPCX accepts `xyz:SPCX` or `xyz:SPACEX`; SKHYNIX accepts `xyz:SKHYNIX` or `xyz:SKHX`), resolved live, never hard-coded indices.
- **Signing.** A port of the official `hyperliquid-python-sdk` signing (msgpack + EIP-712), using audited `@noble/hashes` and `@noble/curves`. It matches **all 22 official SDK vectors**, including every mainnet L1 vector. The exact bundle embedded in `index.html` was re-checked.
  - The backend ships the same bundle in `src/vendor/hlsign.mjs` (no new npm dependency), pinned by SHA-256 in `tests/static.test.js`. The backend only **recovers** signers; it never signs.

## Security controls
| Control | Where |
|---|---|
| Real money needs 4 locks: `HL_EXECUTE_VERIFIED` (backend code), `HL_EXEC_ENABLED` (frontend code), `HL_EXECUTION_ENABLED=1` (env), market in `HL_VERIFIED_MARKETS` | hl-exec.js, saturn-r128-hl, env |
| No user key ever stored. The trading key is generated by Saturn and approved by the user. Hyperliquid agents **cannot withdraw or transfer**. It lives in sessionStorage (this tab only) and is approved with `valid_until` ≤ 30 days; the relay refuses longer approvals | frontend + relay |
| What is signed is explained in plain words before each wallet prompt (ApproveAgent, Withdraw, SendAsset) | frontend |
| Network: explicit "Confirm Hyperliquid mainnet" per address. The wallet network is never switched, except one user-tapped "Switch to Arbitrum One" inside Deposit | frontend |
| Action allowlist: approveAgent, order, cancel, cancelByCloid, updateLeverage, withdraw3, sendAsset. Refused: usdSend, spotSend, vault, builder fee, abstraction changes, sub-accounts, `expiresAfter`, builder field | relay |
| Signatures recovered server-side. User-signed actions must recover to the claimed user. L1 actions must recover (mainnet phantom agent) to an agent Hyperliquid lists for that user and not expired | relay |
| Mainnet only (`hyperliquidChain: Mainnet`; testnet-signed L1 recovers to an unknown key and is refused) | relay |
| Replay and idempotency: durable row per `sha256(signer:nonce)`; nonce must be fresh (−10 min / +1 min); one order per client order id (cloid) per user; triple-tap sends one order | relay + migration 004 |
| Limits: order size cap (default $50), leverage cap, $10 minimum, size decimals, IOC price within slippage cap (default 3%) of **Hyperliquid's own mid fetched by the server**, resting limit within 20% band | relay (and mirrored in the form) |
| Transfers only to the user's own address: withdraw3 ($2–cap), sendAsset (USDC only, main ↔ xyz) | relay |
| Rate limits: per IP, per user, per user orders, shared upstream budget | relay |
| Ambiguous upstream (timeout/5xx) → `unknown`, never retried. The app then asks Hyperliquid `orderStatus` by cloid | relay + frontend |
| Audit table `perps_hl_requests`: no signatures, keys or raw IPs (16-char hash only); 90-day retention | migration 004 |
| Reduce-only closes are allowed even for unverified markets, so users can always exit | relay |

## Collateral (Hyperliquid's real flow)
- **Deposit**
  - Route: native USDC on Arbitrum One (`0xaf88…5831`) transferred from the user's wallet to Bridge2 `0x2Df1c51E09aECF9cacB7bc98cB1742757f163dF7`.
  - Minimum 5 USDC; smaller deposits are lost, so the app blocks them. Credited in about 1 minute. The user pays Arbitrum gas.
  - Saturn shows "credited" only when Hyperliquid's own ledger (`userNonFundingLedgerUpdates`) shows the deposit.
- **Withdraw:** `withdraw3`, signed by the user's wallet, to the user's own address only. $1 fee, about 5 minutes. Shown as recorded only from the ledger.
- **Trade.xyz:** "Separate balances" accounts keep a separate USDC balance for xyz. The app offers "Move to Trade.xyz" (user-signed `sendAsset` to own address). Unified accounts need no move. The mode is read from `userAbstraction`.
